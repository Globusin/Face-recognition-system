# P8 — оптимизация детекции

Переключение: в config.yaml указать face_detection.backend: haar или yunet.
Модель YuNet устанавливается автоматически при запуске `./setup.sh` независимо
от выбранного детектора, чтобы затем можно было переключаться без скачивания.
Повторная установка использует локальную модель, если её SHA-256 совпадает.
Для уже настроенной системы можно обновить только модель, без повторной
настройки PostgreSQL и Vue:

```bash
./venv/bin/python scripts/install_yunet.py
```

Перезапустить backend. По умолчанию сохранён Haar; отсутствие модели YuNet
не приводит к скрытому переключению. Модель OpenCV Zoo (2023mar) проверяется
по SHA-256 при установке. Данные и модель не скачиваются при аутентификации.

## Сравнение детекторов

Подготовить локальный JSONL с одной строкой на кадр: image — путь относительно
манифеста, boxes — все лица в формате x,y,w,h исходного изображения.
Пример формата (не экспериментальные данные):

```json
{"image":"sample.jpg","boxes":[[100,120,160,180]],"condition":"normal"}
{"image":"empty.jpg","boxes":[],"condition":"empty"}
```

Включить разные ракурсы, дистанции, освещение, кадры без лиц и с несколькими
лицами. Использовать одинаковые изображения для обоих детекторов.

```bash
python scripts/benchmark_face_detectors.py data/p8/manifest.jsonl --threads 1 --repeats 5 > data/p8/detectors.json
```

Сравниваются precision, recall, доля ошибок требования одного лица при IoU ≥ 0.5,
mean/p50/p95/p99 задержки. Это не AP и не FRR всей системы.
Haar использует существующую ширину до 640, YuNet — настраиваемую ширину
(320 по умолчанию). Для сравнения при одинаковом размере выставить 640 у YuNet.
Отдельно фиксировать температуру Raspberry Pi, модель платы, загрузку CPU,
версии ПО и разрешение. Результаты замеров пока отсутствуют.

## Эксперимент ложных отказов на стенде

Для каждого предъявления оператор заранее назначает уникальный attempt_id,
детектор, genuine (зарегистрированный участник — true), ожидаемый ID участника.
Одинаковые участники, условия и число попыток для Haar и YuNet; чередовать
порядок детекторов и не менять политику, пороги или базы между сериями.
Разделить подлинные предъявления и незарегистрированных участников.
Отдельно оценивать спуфинг (не объединять его с обычными impostor-попытками).
Задать заранее окно предъявления, например 20 секунд, включая поиск лица.
Записывать ВСЕ предъявления, не только начатые сессии. Если за окно сессия
не появилась, записать NO_SESSION. Для начатой сессии сверять итог и session_id
с административной историей; при нескольких сессиях учитывать заранее
определённую первую сессию в окне. Не включать данные биометрии в отчёт.
elapsed_seconds — время от начала предъявления до результата или конца окна.

Пример синтетического формата (не результат испытаний):
```json
{"attempt_id":"H1","session_id":"sample-session","detector":"haar","genuine":true,"expected_user_id":7,"decision":"DENIED","user_id":null,"reason":"face_lost","elapsed_seconds":2.5}
{"attempt_id":"Y1","session_id":null,"detector":"yunet","genuine":true,"expected_user_id":7,"decision":"NO_SESSION","user_id":null,"reason":"no_face","elapsed_seconds":20}
```

```bash
python scripts/evaluate_authentication.py data/p8/attempts.jsonl > data/p8/authentication_metrics.json
```

FRR end-to-end = число недопусков (DENIED/ERROR/NO_SESSION) среди подлинных
предъявлений / число всех подлинных предъявлений. Неверный ID при допуске
считается отдельной ошибкой; также выводится доля неуспешной правильной
аутентификации. Доля допуска незарегистрированных — отдельная метрика
конкретного протокола, не лабораторный FMR. Реальные измерения не выполнены.

## Проверка после развёртывания

```bash
python -m unittest tests.test_detector_backends tests.test_detector_benchmark tests.test_embedding_worker_p8 tests.test_p8_evaluation tests.test_p8_pipeline
python -m unittest tests.test_authentication tests.test_face_observations tests.test_adaptive_recognition tests.test_face_detection_preview
```

Сквозной регрессионный тест использует реальные маршрутизацию детектора,
источник наблюдений, конвейер распознавания и автомат допуска; камера,
вычисления модели, БД, проверки живости и замок подменены. Это не проверка
физического стенда. Для каждого backend на Pi отдельно проверить:
регистрацию, штатный допуск, незарегистрированного участника, несколько лиц,
потерю лица, обязательные stereo/challenge, отмену и повторную попытку.
Проверить открытие и закрытие замка, состояние UI, запись административной истории.
Сначала использовать безопасный тестовый исполнитель вместо реальной двери.

В логах разделены подготовка ROI, отправка IPC, ожидание IPC и собственное
время dlib (вложенное в ожидание, не суммировать повторно), поиск БД и ожидание
финального наблюдения. При отмене незавершённое задание удаляется до следующей
сессии; прогрев процесса может увеличить время поиска до начала сессии.
Порог сходства и минимальное число свидетельств не изменены. Перенос ROI в
родительский процесс не изменяет геометрию, padding и параметры модели.
